Whenever writing repository content speak plainly and simply, avoiding rhetoric tricks or flowery language. Let the code speak for itself, and provide extra context only where it will be needed for future colleagues. This applies to any prose and includes code comments, documentation, and Git strings like commit messages and PR descriptions.

Plain writing does not mean short sentences. Write connected prose, joining related points into sentences of ordinary length and using linking words such as "because", "so" and "which" to show how one point leads to the next. Avoid runs of clipped sentences and sentence fragments, which read as jarring and disjointed.

Code comments should only contain information that lasts as long as the code. Discussion of changes happen alongside the change itself, in commit messages and PR descriptions.
